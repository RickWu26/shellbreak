# 小红书小工具迁移计划

## 目标

在独立目录生成离线小红书小工具版本，TapTap 与桌面版本保持不变。包体硬上限为 10 MiB；制作阶段目标控制在 9 MiB 左右，留出 ZIP 元数据和后续微调空间。当前授权范围包括隔离改造、静态检查、打包和上传自测/预览；不包含送审。

## 阶段与验收门

1. **冻结本地基线并做素材分支**：基于当前工作区生成单独的 XHS 素材；移除 BGM、全屏背景素材与最大奇观图；其余栅格图转为 WebP，保留矢量图与字体。检查图片路径映射、透明度和包体。
2. **清理离线入口与 CSP**：去掉内联引导脚本及 `document.write`，强制 zh-CN；清理 HTML 和运行时模板里的内联事件属性；保持经典外链脚本和现有装配顺序。
3. **替换平台能力**：将存档与设置迁移到小红书 Storage API（9.46+）；启动前完成异步读档，保存失败不能冒充成功。关闭 TapTap 广告、排行和平台专用存档入口；小红书没有对外广告/支付能力时，不把 `rewardAuthor` 当广告或游戏内购买。
4. **兼容性适配**：检查 Chrome 61 的 JS/CSS/Web API 基线；背景和奇观缺图位置提供本地样式回退；全程只显示简体中文。
5. **产物审计**：运行小工具规范的静态审计，检查资源引用、禁用能力、压缩包结构与 ZIP 体积；只在所有硬门通过后交付 ZIP。
6. **平台验证与送审**：用户已授权上传到创服平台做模拟器/预览自测；Android/iOS 真机另行验证。送审仍需另行决定，当前不执行。

## 当前已确认的技术阻塞

- 主入口包含内联脚本和 `document.write`，页面及动态模板中还存在内联 `onclick` 属性，违反离线容器 CSP。
- 代码有大量同步 `localStorage` 读写；小红书 Storage 是异步 API，必须解决启动前 hydration、串行持久化、写入失败和旧档迁移。
- 去掉 `assets/backgrounds/` 会影响科技/市政纹理、过场动画和天穹界面；需要为这些位置提供代码/CSS 回退，不能只删文件。
- 游戏有 TapTap 广告、排行和原生存档分支；小红书当前公开文档没有等价的游戏广告与支付 API。
- 星图面板使用 iframe 加载独立 HTML，含内联脚本和宽松 CSP；小红书容器禁止 iframe 与内联脚本，需要重做星图或给 XHS 版提供明确降级。
- 素材优化后仍须验证最终 ZIP；创服平台和两类真机验证没有在本地产物审计中替代。
