## 0. 一句话（本稿核心）

**两层界面**：外层「帷幕」只做路径选择——三张卡，每张只有飞升路径的**名字 + 门徽图 + 开启态**，不显示任何树 / 节点 / 进度；内层「飞升操作界面」放进**弹窗**，点已开启的路径才加载。飞升路径**随大轮回逐次解锁**：每次飞升开一条，第三次飞升全部开启。

---

## 1. 信息架构（两层）

| 层 | 承载 | 内容 | 交互 |
|---|---|---|---|
| 外层 · 帷幕主界面 | 三个路径卡 | 名字 + 门徽图（closed/open 两态）+ 开启状态徽标 + 一句操作提示 | 未开启 + 有名额 → 点它开启；已开启 → 点它开弹窗 |
| 内层 · 飞升操作界面 | 弹窗（模态） | 该飞升路径真正的操作界面（树 / 装配台 / 面板） | 弹窗内独立交互，关闭回到主界面 |

**关键纪律**：
1. 主界面**不放树、不放节点、不放进度条、不放 meta 红字**——这些全属于弹窗内的操作界面。
2. 弹窗**按需加载**，不在主界面常驻 DOM（demo 里点开才 `createElement('iframe')`）。
3. 一个弹窗同时只开一个路径。

---

## 2. 逐次解锁规则（本稿关键机制）

| 飞升次数 | 本次可开名额 | 累计可开路径 | 说明 |
|---|---|---|---|
| 第 1 次飞升 | 1 | 1 / 3 | 玩家三选一 |
| 第 2 次飞升 | 1 | 2 / 3 | 再选一条（不含已开） |
| 第 3 次飞升 | 1 | 3 / 3 | 最后一条，**此时全部开启** |
| 第 4 次及以后 | 0（已全开） | 3 / 3 | 路径全部可进入，转为在各操作界面内投入 |

**状态字段**（demo 口径，实装时并入存档）：
- `count` = 累计飞升次数（= 当前帷幕重数）
- `opened[]` = 已开启路径 id 列表（`si` / `vo` / `gn`）
- `quota` = 本次剩余开启名额，推导式 `quota = clamp(count - opened.length, 0, 1)`

**门徽两态**：只由「该路径是否已开启」决定——`opened` 含它 = open 图，否则 closed 图。与是否投入、投入多少无关（那是弹窗内的事）。

**已拍板（2026-11-17 第二轮）**：
1. **每次飞升强制开一条**——不设「本次不开」选项；每次飞升即授予 1 个名额，必须在本次用掉。
2. **名额不能累积**——`quota` 封顶 1，本次不用即作废（既然强制开一条，也不会出现剩余名额）。推导式 `quota = clamp(count - opened.length, 0, 1)` 维持不变。
3. **全开后保留三张卡当永久入口**——第三次飞升全开后，三张卡不退场、不并入总览页；它们是三条飞升路径的长期入口，虚境/基因界面做好后也从这里进。
