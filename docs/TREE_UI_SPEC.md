# 科技树 / 市政树界面规格

当前界面记录：2026-11-15。这里记录已确认的视觉规则和代码中的实际行为，作为两棵研究树后续修改的共用基准。玩法判定仍分别由 `src/tech.js` 与 `src/civics.js` 管理。

## 页面结构

- 科技页依次显示自动研究开关、纪元导航和横向科技长卷。所选纪元的风味说明放进对应纪元横幅；卡片保留节点本身需要的信息。
- **纪元详情卡已移除**（2026-11-16，用户明确要求）：`.eracard` / `.edesc` / `#eraDetail` 三样都不再出现，纪元说明只剩长卷横幅的 `.tnflavor`。随之下线的还有「本纪元关键节点 N/M」闸门进度、下一纪元预告与 ERA10 终局通关说明——关键节点身份只在节点详情浮层的 note 里说明。回归 `calendar-warmstone.mjs` 以反向判据（三者计数必须为 0）守住这条。
- 纪元导航负责显示进度并跳到对应长卷位置。未来纪元可以显示导航状态，但科技节点要到抵达该纪元后才进入画布。
- 科技树是一张横向滚动的连续画布：列按 `layer` 推进，行用于整理分支，前置关系用 SVG 曲线连接。跨纪元只留规定的列间距，不把树拆成彼此独立的面板。
- 市政页保留自己的政体、政策卡和市政树分区；市政树单独使用 `civicScroll`，不与科技树抢滚动位置。

## 统一几何

科技树的 `SB.tech.geo` 是窄屏卡片几何的来源；桌面版使用 `SB.tech.desktopGeo`，市政树读取同一组对应参数。布局坐标由几何与节点关系共同计算。

| 参数 | 值 | 含义 |
|---|---:|---|
| `W × H` | `156 × 106 px` | 卡片外框尺寸 |
| `COL` | `94 px` | 卡片之间的水平留白；列节距为 `250 px` |
| `ROW` | `20 px` | 卡片之间的垂直留白；行节距为 `126 px` |
| `PADX / PADY` | `46 / 52 px` | 画布边缘留白 |
| `ERAPAD` | `30 px` | 相邻纪元列组之间额外留白 |

桌面端（视口宽度至少 761px）使用横向加宽卡片：`W × H = 255 × 100 px`、`COL = 54 px`，列节距为 `309 px`，行节距为 `120 px`；边缘留白与纪元间额外留白沿用窄屏规格。窄屏继续使用上表的紧凑卡片。

节点坐标只由对应 `layout()` 产生，渲染器读取 `cell.x / cell.y`。不要在 CSS 或渲染器里另算卡片位置、卡片尺寸或画布行节距。

## 依赖图与连线

- 科技与市政共用 `SB.treeLayout.orderRows()`：先按节点初始顺序排列，再交替从前向后、从后向前扫描依赖图，运行 12 轮并保留估算交叉数最低的顺序。
- 科技的 `treeRow` 是明确的固定行锚点；其他节点由依赖关系自动排布。市政的 `layoutOrder` 是初始阅读偏好，不再锁死最终行序。
- 市政布局把 `reqs` 与 `reqsAny` 都纳入边图，并继续由市政渲染逻辑生成对应连线。连线状态、揭示规则和研究门槛不因排序而改变。
- 连线从前置卡片右侧接到后续卡片左侧，绘制在节点下层。科技只在连线两端的节点都可见时绘制，避免线悬空。

## 卡片视觉与信息层级

- 科技与市政在所有屏幕共用卡片结构、金属感外框、内容底色、标题行、状态底栏、进度条和交互反馈；完成、可研究、暂不可研究、未揭露四种视觉状态使用同一套状态标记。卡片按纪元映射到六种边框图，内容底色裁在边框内。
- 科技树的窄屏卡片保持 156 × 106 px 基准尺寸；桌面卡片扩为 255 × 100 px，卡间留白维持各自几何规格。已揭示科技的建筑/奇观解锁效果以小图标表达，不在卡片内重复铺成长效果文案。
- 所有屏幕上的已揭示科技仅用建筑和奇观图标表达解锁；窄屏沿用紧凑卡片尺寸与横向卷动，同时使用纪元边框和背景。卡片同时显示科技研究点不足进度。
- 两树用类别色区分：科技偏青，市政偏金。日间与夜间分别提供可读的表面、文字、边线和进度色；昼夜主题不改变状态语义。移动端与桌面端保持同一套卡片视觉，按屏幕仅采用相应卡片几何。
- 已完成节点使用绿色完成标记；当前可研究节点用金色边缘呼吸提示；已揭示但暂不可研究节点保持低强调；未揭露节点隐藏真实名称与效果，只显示揭示条件和进度。
- 科技卡片显示科技图标、名称、关键/挑战标记、适用的尤里卡条件与进度，以及状态、追踪和详情入口。尤里卡只揭示科技，不折算研究进度。
- 市政卡片保留对应的三态规则：已完成、已揭示可研究、未揭露；鼓舞只揭示市政，不替玩家支付市政点。
- 详情卡在桌面端从右侧展开，窄屏时贴近底部并可滚动。卡片保持紧凑，完整效果与研究操作在详情卡中展示。

## 背景与主题

- 科技树与市政树使用同一组纪元背景素材：画布中按纪元连续铺接，边缘保持暗色、中部以低细节建筑作视觉锚点，并在纪元交界处轻微重叠以消除细缝。
- 昼夜主题只调整同一背景层的明暗和饱和度；卡片、连线与文字保持前景层级。日间模式下背景图仍应可辨认，同时维持卡片文字对比。
- 用户确认的背景素材方向：边缘用一致暗色，中间只展示少量低细节建筑；纪元 4 体现深海文明，纪元 5 突出钻机。新素材进入全页纪元背景序列，科技树与市政树使用同一背景。

## 不应随视觉排版改变的规则

- 不改科技 / 市政的 `reqs`、`reqsAny`、揭示条件、研究成本、纪元门槛、完成判定或自动研究门槛。
- 不把科技尤里卡与市政鼓舞做成研究进度折扣。
- 不共用两棵树的滚动容器或玩法状态；只共用展示几何、依赖行序算法和视觉样式。
- 增加或调整玩家可见文案时，先按 `docs/I18N_TEXT_GUIDELINES.md` 更新文本清单并通过语义键引用。本文仅记录既有规则，不引入新界面文案。
